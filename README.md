# Система управління студентами

Навчальний вебзастосунок для обліку студентів, груп, дисциплін і оцінок.
Наскрізний проєкт дисципліни «Технології проєктування та розробки мережевих ресурсів».

## Запуск
Потрібен менеджер проєктів [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run student-portal
```

Дані читаються з `data/group.json` відносно поточної папки та зберігаються
атомарно під час виходу (пункт 0). Запускайте команду з кореня репозиторію.

Журналювання вимірювань увімкніть змінною `LOG_LEVEL`:

```bash
LOG_LEVEL=INFO uv run student-portal
```

Типовий рівень — WARNING. INFO показує тривалість імпорту, експорту,
розсилки та збереження. Розсилка є імітацією, справжніх листів не надсилає.

## Журнал оцінок
Пункт 9 імпортує CSV з роздільником `;` та кодуванням UTF-8 (з BOM або без).
Приклад `data/journal.csv`:

```csv
student_id;course;score;graded_on
1;Вебтехнології;91;2026-10-20
```

Імпорт виконується за правилом «все або нічого»: помилка будь-якого рядка
відновлює попередній стан групи. `data/journal-broken.csv` містить бал 105
у рядку 4, тому нічого не додає. Повторний успішний імпорт додає оцінки
повторно; автоматичного усунення дублікатів немає.

Пункт 10 імітує розсилку з лімітом трьох одночасних завдань.
Пункт 12 (варіант 4 ЛР3, перенесено з 11 у ЛР5) експортує всі оцінки через генератор рядків,
`csv.DictWriter` та `atomic_write` у UTF-8 з BOM для Excel. Дати й оцінки
зберігаються без втрат при імпорті у ту саму групу з очищеними оцінками.

## Перевірки

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src
```

mypy працює у суворому режимі. Для 5 студентів із затримкою 0,5 с
послідовна розсилка займає приблизно 2,5 с; `notify_all` із лімітами
1, 3 та 5 — відповідно 2,5, 1,0 та 0,5 с. Блокуючий `time.sleep`
всередині співпрограми знову дає приблизно 2,5 с. У робочому коді
залишено `await asyncio.sleep`.

## Тести
ЛР4–6: модульні тести ядра та інтеграційні тести Django з pytest-django.
Для тестів потрібен локальний `.env` із ключем Django.

```bash
uv run --env-file .env pytest
uv run --env-file .env pytest --cov
uv run --env-file .env pytest -k ranking
uv run --env-file .env pytest -v tests/test_django.py
```

Тести використовують незалежні фікстури, tmp_path, monkeypatch, capsys
і caplog; не змінюють файли в data/. Повторний запуск, окремі модулі
та зворотний порядок дають той самий результат. Реальні затримки,
мережа та виклик main() у тестах не використовуються.

Знайдений тестами дефект: Group.find не враховував пробіли навколо
запиту. Виправлено окремим комітом: запит очищається через strip().

## Сервер деканату
Пункт 11 завантажує групу й замінює поточну лише після відповіді `т`.
Адресу задає `DEKANAT_URL`; типовий URL є прикладом, реального сервера немає.
Для локальної демонстрації у першому терміналі:

```bash
uv run python -m http.server 8001 -d data
```

У другому терміналі:

```bash
DEKANAT_URL=http://127.0.0.1:8001/group.json uv run student-portal
```

Після вимкнення сервера пункт 11 повідомляє про помилку і повертається в меню.
Експорт CSV варіанта 4 збережено у пункті 12.

## Покриття і CI
ЛР5: 144 тестові випадки. Мережеву функцію підмінено в `remote`, а виклик
завантаження — в `cli`. AsyncMock перевіряє кількість очікувань, порядок і
ліміт активних завдань. Тести не потребують мережі та не змінюють `data/`.

```bash
uv run --env-file .env pytest --cov
uv run --env-file .env pytest --cov --cov-report=html
uv run ruff check .
uv run ruff format --check .
uv run mypy src
```

HTML-звіт: `htmlcov/index.html`. Покриття операторів і всіх 84 гілок — 100%,
поріг coverage.py — 90%. У `journal`, включно з експортом варіанта 4,
також покрито 100% гілок. До додавання нових тестів покриття було 80,62%.

GitHub Actions має незалежні завдання `checks` (Ruff, форматування, mypy)
та `tests` (pytest з branch coverage). `uv sync --locked` перевіряє lock-файл;
артефакт `coverage-html` зберігається навіть після невдалих тестів.
Правило `main` вимагає успіху обох перевірок перед злиттям PR.

## Вебзастосунок Django

Проєкт `config` містить загальні налаштування й кореневі маршрути.
Застосунок `students` використовує ядро `student_portal` для читання JSON,
рейтингу та оцінок ECTS. Ядро не залежить від Django.

Створіть `.env` на основі `.env.example` і вставте власний випадковий ключ у
`DJANGO_SECRET_KEY`. Значення можна отримати командою
`uv run python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`.
Файл `.env` та локальна база `db.sqlite3` ігноруються Git.

| Змінна | Приклад | За замовчуванням |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | випадковий ключ | немає; без нього Django не запускається |
| `DJANGO_DEBUG` | `1` для локальної роботи | `0` |
| `DJANGO_ALLOWED_HOSTS` | `"127.0.0.1 localhost"` | порожній список |

```bash
uv sync --locked
uv run --env-file .env python manage.py migrate
uv run --env-file .env python manage.py runserver
uv run --env-file .env python manage.py group_stats data/group.json
```

### Сторінки

| Адреса | Що показує | Представлення |
| --- | --- | --- |
| `/students/` | Список і пошук за прізвищем `?q=` | `student_list` (FBV) |
| `/students/<id>/` | Картка студента й оцінки ECTS | `student_detail` (FBV) |
| `/students/<id>.json` | Ім’я та середній бал у JSON | `student_json` (FBV) |
| `/students/ranking/` | Рейтинг групи | `RankingView` (CBV) |
| `/students/pages/` | Список по два студенти, `?page=` | `StudentListView` (CBV) |
| `/students/debtors/` | Боржники з дисциплінами Fx (ЛР6) | `debtors` (FBV) |

Спільний `base.html` підключає `students/style.css`; рейтинг використовує
тег включення `student_card` (варіант 4), а список — фрагмент `student-row`.
Для збирання статичних файлів перед розгортанням:

```bash
uv run --env-file .env python manage.py collectstatic --noinput
```

Зібрані файли у `staticfiles/` локальні й не додаються до Git.
Приклад: <http://127.0.0.1:8000/students/>.
Команда `group_stats` завершується з кодом 1 для відсутнього або пошкодженого
файлу. CI використовує окремий відкритий ключ лише для тестів і запускає
`manage.py check` та `makemigrations --check --dry-run`.
